# Spec: Swarm Worker 异步后台化 Shell（防卡死执行机制）

## Problem Statement

在 `pi-swarm` 中运行多 Agent 协作时，当 `verifier`（或任意普通 worker）通过 `bash` 工具执行一个长期运行或不会主动退出的命令（例如开发服务器、watch 模式测试如未带 `--run` 的 `vitest`、端口监听、等待交互输入的脚本或死锁进程）时，会出现严重的假死问题：

1. **工具调用永久阻塞**：Pi 内置的 `bash` 工具默认没有任何超时限制，会同步死等子进程退出，导致该 worker 永远卡在单次工具执行中无法返回。
2. **状态误报导致监控失明**：卡死期间，该 worker 的状态始终保持为 `working`。由于 `swarm-monitor` 将“只要有任意成员处于 `working`”视为正常长构建，monitor 永远不会触发 stall 告警，`coordinator` 与用户也难以察觉任务已经停滞。
3. **简单硬超时存在严重权衡问题**：如果粗暴地给所有 `bash` 命令加上较短的固定总时长超时并强杀进程，又会误杀合法的长耗时命令（如大型编译、全量集成测试、构建打包），导致验证与开发任务反复中断、无法推进。

## Solution

为 `pi-swarm` 中的 worker 引入对齐 Antigravity `run_command` 模型的**异步后台化 Shell 机制**，从根源上消除“挂起卡死”与“误杀长任务”之间的二选一矛盾：

1. **短命令同步返回，长命令自动转后台（不杀进程）**：worker 执行 shell 命令时支持等待窗口（`wait_ms`）。命令在窗口内完成则像现在一样同步返回退出码与输出；超过窗口仍未退出时，系统**不终止进程**，而是将其转交运行时后台托管，立刻把进程任务 ID 与当前已捕获的输出返回给 worker，释放当前 turn。
2. **事件驱动的异步唤醒**：后台命令自然结束时，运行时复用现有 worker 异步唤醒通道自动唤醒所属 worker，送回退出码与尾部日志；对于非守护进程（non-daemon）且长时间未结束的命令，到达提醒超时后同样唤醒 worker，附上已运行时长、无输出静默时长与最新尾部日志，由 worker 自行决定继续等待、发送输入还是终止进程。
3. **完整的后台进程控制与可见性**：为 worker 提供专用的后台进程管理工具（查询列表、查看状态与最新输出、发送标准输入、按进程树终止）；同时在看板状态快照与 TUI 视图中展示活跃后台进程，让 `coordinator`、`monitor` 和用户都能清晰区分“正常长任务”与“挂起假死”。
4. **严格的生命周期清理**：当 worker 被永久终止、整个 swarm 停止或会话关闭时，运行时自动清理该 worker 名下的所有存活后台进程树，杜绝孤儿进程与端口占用泄漏。

## User Stories

1. 作为 `verifier`，我希望执行短耗时命令（如单测、类型检查、`git diff`）时在等待窗口内直接同步拿到退出码和输出，以便常规验证流程保持零额外往返开销。
2. 作为 `verifier`，我希望执行不主动退出的命令（如 dev server、watch 模式测试）超过等待窗口后自动转入后台并返回任务 ID 与已有输出，以便我的 turn 不会被永久阻塞在工具调用里。
3. 作为 `verifier`，我希望在长耗时构建或全量测试转入后台后进程不会被强行杀死，以便合法的慢命令可以完整跑完而不前功尽弃。
4. 作为 `verifier`，我希望后台命令执行完毕时运行时自动唤醒我并附上退出码与最新输出尾部，以便我无需手动轮询即可继续完成验证并回报结果。
5. 作为 `verifier`，我希望在启动后台开发服务器后能够标记其为守护进程（daemon），以便我可以在同一轮或后续轮次对服务发起接口/端到端校验，且不会收到多余的“仍在运行”超时告警。
6. 作为 `verifier`，我希望在端到端校验结束后能主动终止自己启动的后台守护进程树，以便及时释放监听端口和系统资源。
7. 作为 `verifier`，我希望当非守护后台命令超过提醒时间仍未退出时收到包含已运行时长、无输出静默时长和最新日志尾部的提醒唤醒，以便我能及时识别 watch 模式或卡死命令并将其终止。
8. 作为 `verifier`，我希望能够随时查看自己名下所有后台进程的状态和最新日志输出，以便判断某个长任务是否仍在推进。
9. 作为 `verifier`，我希望能够向正在运行的交互式后台进程发送标准输入，以便处理简单的确认提示或按指令退出交互程序。
10. 作为 `verifier`，我希望在后台命令已完成但此时我正忙于另一个 turn 时，完成通知不会丢失而是在我当前 turn 结束后立即投递，以便我不会遗漏后台验证结果。
11. 作为 `verifier`，我希望命令转入后台时系统明确告知不要在循环中轮询等待，而是结束 turn 等待异步唤醒或处理其他任务，以便避免浪费 token 空转。
12. 作为 `author`，我希望也统一使用这套异步后台化 shell 能力，以便我在执行长编译或启动本地服务调试时同样不会卡死 worker 会话。
13. 作为 `author`，我希望自己只能查看、输入和终止自己启动的后台进程，而不能误操作其他 worker 的后台进程，以便多 worker 并行运行时互不干扰。
14. 作为 `monitor`，我希望在调用看板状态快照时能看到每个 worker 当前挂载的活跃后台进程（含命令摘要、是否 daemon、已运行时长和无输出静默时长），以便区分“全员真的空闲死锁”与“正在等待后台构建完成”。
15. 作为 `monitor`，我希望当某个 worker 名下仅有长期静默的非 daemon 后台进程且长时间无人处理时能准确识别异常并提醒 `coordinator`，以便彻底消除假死盲区。
16. 作为 `coordinator`，我希望通过状态查询就能一眼看到各个 worker 挂着哪些后台进程及其运行/静默时长，以便在任务推进缓慢时快速定位瓶颈。
17. 作为 `coordinator`，我希望当一个 worker 被我永久 `kill` 时，它启动的所有后台进程树会被一并彻底清理，以便不会留下僵尸进程或占住端口影响后续新 worker。
18. 作为使用 `pi-swarm` 的用户，我希望在执行停止全部 worker 或退出 Pi 会话时，所有 swarm worker 启动的后台进程都被自动清理，以便退出后系统里不残留失控子进程。
19. 作为使用 `pi-swarm` 的用户，我希望在 TUI 的状态组件和详情面板中看到 worker 的活跃后台进程数量与摘要，以便直观感知当前谁在等后台构建、谁起了本地服务。
20. 作为使用 `pi-swarm` 的用户，我希望后台进程输出过大时日志仍被安全截断并保留尾部关键信息（必要时落盘完整日志路径），以便不会撑爆模型上下文窗口或内存。
21. 作为使用 `pi-swarm` 的用户，我希望无论在 Windows 还是类 Unix 环境下终止后台进程都能杀掉整棵子进程树（而不只是顶层 shell），以便像 `npm test` 派生出的子进程不会继续挂在后台。
22. 作为 `monitor`，我希望我的身份依然不能执行编码或运行业务 shell 命令，以便保持 stall monitor 的只读观察职责不被破坏。

## Implementation Decisions

### 1. 模块划分与职责边界
- **新增后台进程管理器模块（Background Process Manager）**：封装子进程启动、等待窗口竞争（sync-to-async promotion）、stdout/stderr 增量缓冲与尾部截断、`lastOutputAt` 静默计时、标准输入投递、通知定时器管理、按进程树查杀，以及按 `ownerWorker` 维度的索引与批量清理。
- **扩展 Swarm 运行时管理器（SwarmManager）**：持有后台进程管理器实例；将后台进程退出与提醒超时事件接入现有异步唤醒管线；在 `killTarget`、`stopAll`、`dispose` 生命周期钩子中自动清理对应 worker 的后台进程；将活跃后台进程摘要纳入详细状态与实时快照。
- **扩展 Worker 工具定义与会话工厂**：
  - 所有非 `monitor` 的 swarm worker 默认不再暴露无限阻塞的同步 `bash`，而是由 worker 扩展提供具备异步后台化能力的 `bash` 工具以及配套的后台进程管理工具。
  - `monitor` 保持现有最小权限边界，不引入新的后台业务命令权限，且其专用的定时调度工具（`schedule` / `manage_task`）保持原样，不与进程管理工具混淆。
- **扩展共享类型与状态快照**：在类型定义中新增后台进程摘要结构（任务 ID、归属 worker、命令摘要、运行状态、是否 daemon、启动时间、最后输出时间、已运行时长、静默时长、退出码等），并挂入成员状态摘要与 Swarm 快照。
- **更新 Skill 与 Worker 系统提示词**：更新 worker 系统提示词规则以及 coordinator / monitor 的 Skill 指南，说明后台命令的异步唤醒契约（不轮询、善用 `is_daemon`、用完即 kill 守护进程），以及 `monitor` 在检查状态时如何解读活跃后台进程与长时间静默的非 daemon 进程。
- **更新 TUI 呈现层**：在常驻状态 widget 与交互式 Overlay 的 Workers 视图中展示 worker 的活跃后台进程计数与关键摘要。

### 2. 工具接口契约
- **异步后台化 `bash` 工具（Worker 侧）**：
  - 输入参数包含：
    - `command`（必填字符串）：要执行的 shell 命令。
    - `wait_ms`（可选正整数，默认例如 10000ms，支持合理上限如 30000ms）：转为后台前同步等待的最长时间。
    - `is_daemon`（可选布尔值，默认 `false`）：标识常驻型支撑进程（如 dev server、watcher）；为 `true` 时不启用默认“仍在运行”提醒定时器。
    - `notify_after_seconds`（可选正数）：仅对非 daemon 生效，转入后台后若超过该时长仍未退出则触发一次“仍在运行”提醒唤醒（提供合理默认值，如 120 秒）。
  - 行为契约：
    - 若命令在 `wait_ms` 内退出：同步返回完整结构化结果（退出码、截断后的输出、完整日志路径（如被截断）、耗时）。
    - 若命令超过 `wait_ms` 仍未退出：保持进程继续运行，立即返回已转入后台的提示、唯一进程任务 ID、当前已捕获的输出尾部、当前已运行时长，以及无需轮询等待唤醒的提示。
- **后台进程管理工具（Worker 侧，独立命名以避免与 monitor 的 `manage_task` 冲突，如 `shell_task` / `manage_process`）**：
  - 支持动作：`list`、`status`、`send_input`、`kill`。
  - 权限边界：普通 worker 仅可操作自己名下（`ownerWorker === caller`）的进程；跨 worker 访问返回明确权限拒绝错误。
  - `status` 返回运行态/已退出态、退出码（如已退出）、已运行时长、无输出静默时长及最新输出尾部。
  - `send_input` 向仍存活的进程写入标准输入，并支持明确的错误反馈（进程已退出或 stdin 不可用时报错）。
  - `kill` 终止整棵进程树，并取消关联的提醒定时器，且避免在人为 kill 后再触发多余的完成唤醒。

### 3. 异步唤醒与并发竞态策略
- **扩展唤醒原因（WakeReason）**：在现有 `board`、`schedule`、`model_switch` 之外，新增 `process_exit` 与 `process_still_running` 两类唤醒原因。
- **唤醒优先级与排队**：
  - 当进程退出或提醒触发时，若所属 worker 处于 `waiting`，直接通过 `wakeWorker` 唤醒并附带结构化摘要（进程 ID、命令、退出码或运行/静默时长、最新日志尾部）。
  - 若所属 worker 当前正在 `working` 或正在被唤醒，则将进程事件缓存到该 worker 专属的待投递队列中，待其 `onWorkerSettled` 结算完毕后立即唤醒并批量/按序投递，避免丢通知。
  - 若 worker 已被 `kill` 或 `SwarmManager` 已 `dispose`，静默丢弃后续进程事件。
- **与错误恢复的协同**：若 worker 上一轮因模型错误退出，但后台进程随后正常结束，是否立即唤醒应保持安全一致（不因残留错误状态吞掉进程完成事件，或明确保留未投递通知供换模型后恢复）。
- **静默时间追踪**：每次收到子进程 stdout/stderr 数据块即更新 `lastOutputAt`，确保提醒通知与状态查询能精准反映“卡死多久无输出”与“总计运行多久”的区别。

### 4. 进程树清理与平台兼容性
- 复用 Pi 现有的跨平台 shell 启动与进程树查杀策略（类 Unix 通过独立进程组查杀，Windows 通过进程树查杀），确保 `npm` / `vitest` / `node` 多层派生子进程被完整清理。
- 对已退出的后台进程记录保留有限历史（或标记为 `exited` / `killed`）供同会话查询，但在状态摘要中明确区分活跃进程与历史已结束进程，防止内存无限增长。
- 后台进程属于内存态 OS 进程，不试图跨 `/resume` 或进程重启恢复旧 PID；重启恢复时活跃进程列表自然为空。

### 5. 与现有 `swarm-monitor` 协作约定
- 在 `read_board{status: true}` 的详细状态输出中，为每个拥有活跃后台进程的 worker 附加后台进程摘要（任务 ID、是否 daemon、命令预览、已运行时长、无输出静默时长）。
- 更新 `swarm-monitor` 指导规则：当全员均处于 `waiting` 但存在活跃的非 daemon 后台进程且静默时长尚短时，属于“正在等待后台构建/测试完成”，不误报为 stall；当非 daemon 后台进程长时间静默无进展且无人接管时，向 `@coordinator` 发出包含该进程信息的异常告警。

## Testing Decisions

### 什么是好测试
- **只测外部可观测行为，不测内部实现细节**：通过公共工具接口、状态快照、唤醒提示内容以及真实子进程的存活/退出状态验证行为，不断言私有字段或内部定时器句柄。
- **用真实轻量子进程验证 OS 行为**：使用极短执行时间的真实 `node -e` 子进程配合百毫秒级 `wait_ms` 与 `notify_after_seconds`，直接覆盖真实 stdio 管道、增量输出、标准输入交互与跨平台进程树查杀，避免 mock `child_process` 带来的假绿。

### 测试接缝与覆盖模块
- **主接缝（0 新增 Mock 接缝）**：复用现有 `SwarmManager` + `SwarmManagerOptions.sessionFactory`（`MockWorkerSession`）+ Worker 工具定义接缝。
- **覆盖范围**：
  1. **同步/异步切换行为**：快命令同步返回退出码与输出；慢命令超过 `wait_ms` 自动转后台并立刻返回句柄与已有输出，不杀死进程。
  2. **异步唤醒闭环**：后台进程退出时唤醒处于 `waiting` 的 worker；worker 处于 `working` 时事件入队并在 `onWorkerSettled` 后补发唤醒。
  3. **超时提醒与 daemon 区分**：非 daemon 命令超过 `notify_after_seconds` 触发“仍在运行”提醒唤醒并携带准确静默/运行时长与尾部日志；`is_daemon: true` 不触发超时提醒。
  4. **进程管理工具与权限隔离**：`list`、`status`、`send_input`、`kill` 完整闭环；验证 worker 无法查看或终止其他 worker 的后台进程；人为 `kill` 后不再发送多余退出唤醒。
  5. **生命周期与孤儿进程清理**：验证 `killTarget`、`stopAll`、`dispose` 会真实终止归属该 worker 的所有后台进程（含子进程树）。
  6. **可观测性集成**：验证详细状态快照、`SwarmSnapshot` 与 TUI 渲染包含活跃后台进程摘要。
  7. **端到端会话冒烟测试**：验证通过真实 `createAgentSession` 启动的 worker 实际加载了异步后台化 `bash` 与进程管理工具，而非默认无限阻塞的同步 `bash`。

### 现有测试先例
- 沿用现有运行时测试套件的 `MockWorkerSession` 与 `registerFauxProvider` 端到端测试模式。
- 沿用现有工具测试套件对 TypeBox 参数校验、权限检查、错误消息及 TUI 调用/结果渲染器的测试模式。
- 沿用现有 TUI 测试套件对组件与 Overlay 快照渲染的断言风格。

## Out of Scope

- **`author <-> verifier` 跨轮打回次数熔断**：验证返工乒乓死循环检测与轮次上限控制不在本 Spec 范围内，后续可作为独立特性叠加。
- **Coordinator 侧异步 Shell**：本 Spec 仅针对 swarm worker，不修改主会话 coordinator 或非 swarm 普通 Pi 会话的 `bash` 行为。
- **跨会话重启的进程重连**：Pi 退出或 `/resume` 后不尝试重新接管旧进程，退出时直接清理。
- **通用 Worker 单 Turn Token/Cost 预算熔断**：单轮工具调用次数上限或花费上限不纳入本 Spec。
- **`swarm_wait` 阻塞模型重写**：`swarm_wait` 继续保持现有非阻塞 park 语义，不改为阻塞式等待。

## Further Notes

- **与底层唤醒竞态修复的配合**：在实际落地时，建议一并排查并加固现有的 `wakeCoordinator` 在非 idle 状态下的丢唤醒竞态，以及 worker 报错后丢弃未读唤醒的问题，避免后台进程机制稳定后卡点转移到上层唤醒链路。
- **与后续 Verifier 熔断的正交性**：本 Spec 解决的是“单次验证命令卡死导致假 `working`”；后续若引入“跨轮打回次数熔断”，两者完全正交，可直接叠加在 `SwarmManager` 之上。
- **输出截断一致性**：后台进程日志缓冲应与 Pi 既有终端输出截断策略保持一致（保留尾部窗口，超限时落盘临时文件并返回路径），兼顾排障完整性与上下文开销控制。
